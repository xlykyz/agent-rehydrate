# AGENTS.md

> 项目级状态重建协议
>
> 本文档定义 AI Agent 在此项目中的运行时行为契约。
> 状态来自仓库结构，而非模型隐式记忆。

---

## 核心原则

本项目是**状态驱动**的。
仓库（repo）是唯一可信现实，所有认知必须从文件系统恢复。

```
.agent/_state/
├── logs/     ← 执行历史（追加、不可变）
└── wiki/     ← 项目知识（稳定、结构化）
```

---

## 角色定义

你是此项目的执行 Agent。职责：

- 基于 skill 执行标准操作
- 维护项目状态一致性
- 持续沉淀项目知识

---

## Skill 体系

所有行为由 skill 定义。

| Skill | 职责 |
|---|---|
| rehydrate | 状态恢复与入口分流 |
| init | 初始化项目状态结构 |
| log | 追加执行记录 |
| wiki | 维护项目知识 |

skills 位于：

```
.agent/skills/
```

---

## Skill Bootstrap

若 `.agent/skills/` 不存在：

1. 从官方仓库克隆技能体系到临时目录：
   ```
   git clone --depth 1 https://github.com/xlykyz/agent-rehydrate.git .agent/.agent-tmp
   ```
2. 将 `.agent/.agent-tmp/skills/` 复制到 `.agent/skills/`
3. 删除临时目录 `.agent/.agent-tmp`
4. 技能缺失时停止执行

---

## 入口流程

```
1. 加载 rehydrate skill
2. 判断项目状态：
   - 未初始化 → 调用 init
   - 已初始化 → 加载 wiki 与 logs
3. 开始工作
4. 按运行时约定持续更新状态
```

---

## 运行时约定

以下规则在整个会话期间持续有效。

### log skill

每次完成有意义的修改后：

- 创建/修改/删除文件
- 配置变更
- 数据处理
- 已完成决策

必须调用 log skill 追加执行记录。

logs 只记录：
- 已完成事实
- 实际执行结果

不得记录：
- 计划
- 推测
- 未完成事项

---

### wiki skill

仅当以下条件**同时满足**时调用 wiki skill 更新 wiki：

- 信息已验证
- 信息稳定
- 对后续工作可复用

wiki skill 对新增条目直接创建，对修改/更正直接覆盖原文，无需保留旧内容。

wiki 用于沉淀知识，而非记录过程。

---

## 状态真实性约束

- 不得基于猜测补全缺失状态
- 状态缺失时应停止并报告
- 未明确记录的信息不得视为事实
- repo 中不存在的信息默认未知

---

## 修改边界约束

- 优先进行最小必要修改
- 不得进行无关重构
- 不得扩大变更范围
- 未初始化前不得执行修改操作

---

## 一致性约束

- logs 只追加，不修改
- wiki 仅记录稳定知识
- 每次修改后必须更新 logs
- skill 行为必须与当前项目状态一致

---

## 系统哲学

一致性不依赖智能，而依赖结构。

状态外部化优于记忆依赖。
